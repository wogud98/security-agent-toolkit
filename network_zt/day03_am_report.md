### 문제 2-1 · 도메인 이름을 IP 주소로 — 두 DNS 서버에 묻기

- (가-1) 처음 `nslookup example.com` 을 쳤을 때, 내가 물어본 DNS 서버의 주소와 example.com 의 IPv4 주소를 적어 주세요.
  - 쓸 내용: 화면 맨 위 `Address` 줄의 주소 하나, 아래쪽 `Addresses` 에서 숫자 네 개를 점으로 이은 주소 하나 — 두 개를 「서버: … / example.com: …」처럼. 맥북은 맨 위 `Address`, 아래 `Name:` 다음 `Address` 줄
  - 답: DNS Server: 168.126.63.1, example.com IPv4:104.20.23.154
```bash
$ nslookup example.com
서버:    kns.kornet.net
Address:  168.126.63.1

권한 없는 응답:
이름:    example.com
Addresses:  2606:4700:10::6814:179a
          2606:4700:10::ac42:93f3
          104.20.23.154
          172.66.147.243

```


- (가-2) `nslookup example.com 8.8.8.8` 을 쳤을 때, 맨 위 `서버` 줄에 나온 이름과 example.com 의 IPv4 주소를 적어 주세요.
  - 쓸 내용: `서버` 줄의 이름 하나(맥북은 `Server`), IPv4 주소 하나. 시간 초과가 났으면 「시간 초과」라고 적어도 됩니다
  - 답: dns.google, 104.20.23.154


- (나) 🔍 화면 위쪽 `Address` 와 아래쪽 `Addresses` 는 각각 무엇의 주소일까요? 두 화면을 비교해서 적어 주세요.
  - 쓸 내용: ① 두 화면에서 바뀐 쪽과 그대로인 쪽 ② 그렇게 된 이유 — 위쪽 · 아래쪽이 각각 무엇의 주소인지를 근거로 쓰기
  - 답: 각각 DNS서버의 주소, 질문한 도메인에 해당하는 주소이다.

- (다-1) 회사 PC 가 회사 DNS 서버 대신 `8.8.8.8` 같은 외부 DNS 서버에 직접 묻고 있다면, 관제 담당자는 왜 이것을 확인해야 할까요?
  - 쓸 내용: ① 회사 DNS 서버가 평소에 하는 일(검색해서 찾아도 됩니다) ② 외부 DNS 에 직접 물으면 그 일을 거치지 않게 되는 까닭
  - 답: *회사 DNS 서버는 도메인 이름을 IP 주소로 변환하는 역할뿐 아니라, 내부 시스템 주소 관리, 악성 도메인 차단, DNS 질의 기록을 통한 보안 관제 등을 수행할 수 있는데, 회사 PC가 8.8.8.8 같은 외부 DNS에 직접 질의하면 회사 DNS의 차단 정책이나 기록을 거치지 않아 악성 사이트 접속을 탐지하거나 내부 도메인을 정상적으로 조회하기 어려워질 수 있기 때문입니다.*

- (다-2) 내 PC 의 DNS 서버 설정이 나도 모르게 낯선 주소로 바뀌어 있다면, 어떤 일이 생길 수 있을까요?
  - 쓸 내용: ① 그 낯선 DNS 서버가 내 질문에 어떤 답을 줄 수 있는지 ② 그 답 때문에 내가 어디로 접속하게 되는지
  - 답: *낯선 DNS 서버가 정상적인 사이트 주소 대신 공격자가 만든 가짜 사이트의 IP 주소를 알려줄 수 있으며, 이로 인해 사용자가 은행이나 로그인 사이트에 접속한다고 생각하면서 실제로는 개인정보와 비밀번호를 탈취하는 피싱 사이트에 접속하게 될 수 있습니다.*

  - 쓸 내용: ① (가-1) 첫 줄의 리스트를 0 번부터 세어 각 칸에 무엇이 있는지 ② `//` 사이에 무엇이 생겼는지
  - 답: 0번부터 https:, 1번 '', 2번 example.com, 3번 news, 4번 today 순서

- (나-2) 두 번째 파일은 왜 마지막 줄에서 에러가 나며 멈췄을까요? `nslookup` 결과와 이어서 적어 주세요.
  - 쓸 내용: ① `gethostbyname()` 이 DNS 서버에 무엇을 물었는지 ② DNS 서버가 어떤 답을 했는지 ③ 그래서 왜 에러가 났는지
  - 답: ethostbyname()이 DNS 서버에 abc.nowhere-not-exist.com의 IP 주소를 물었지만, nslookup 결과 해당 도메인이 존재하지 않는다는 Non-existent domain 응답이 나왔기 때문에 IP 주소를 얻지 못해 socket.gaierror 에러가 발생했습니다.

- (다) 🔍 `Non-existent domain`(NXDOMAIN) 이 나왔다고 인터넷이 끊긴 걸까요? 아니라면 왜 아닌지 적어 주세요.
  - 쓸 내용: ① DNS 서버가 답을 했는지 안 했는지 ② 인터넷이 정말 끊겼다면 화면이 어떻게 달랐을지
  - 답: 인터넷이 끊긴 것이 아닙니다. DNS 서버가 질의에 응답했지만 해당 도메인이 존재하지 않는다고 알려준 것이며, 인터넷 연결 자체에 문제가 있었다면 DNS 서버에 연결할 수 없거나 응답 시간 초과 등의 오류가 나타날 수 있습니다.

  - 쓸 내용: ① 첫 화면은 누가 답했는지 ② 둘째 화면은 누가 답했는지 ③ 그 차이가 왜 그 줄로 나타나는지
  - 답: 첫 화면은 리졸버인 kns.kornet.net이 캐시나 권한 있는 네임서버에서 얻은 정보를 바탕으로 답했기 때문에 권한 없는 응답이라고 표시되고, 둘째 화면은 example.com의 권한 있는 네임서버인 hera.ns.cloudflare.com에 직접 질의했기 때문에 해당 문구가 표시되지 않음

  - 답: 두 응답이 같다면 리졸버가 권한 있는 네임서버의 정보와 일치하는 답을 제공한 것으로 볼 수 있고, 다르다면 캐시된 정보의 차이, DNS 레코드 변경 전파 지연, 설정 오류 또는 변조 가능성 등을 추가로 확인할 수 있음

### 문제 4-1 · 메일 서버와 별칭 — MX · CNAME

- (가-1) `nslookup -type=mx google.com` 에서 메일 서버 이름(`mail exchanger =` 뒤)과 우선순위 숫자(`MX preference`)를 적어 주세요.
  - 쓸 내용: 메일 서버 이름 하나, 숫자 하나. 아래에 같이 나오는 IP 는 적지 않습니다
  - 답: smtp.google.com, 10
```bash
권한 없는 응답:
google.com      MX preference = 10, mail exchanger = smtp.google.com
```

- (가-2) `nslookup www.naver.com` 에서 `Aliases:` 줄의 이름과 `이름:` 줄의 최종 이름을 적어 주세요.
  - 쓸 내용: `Aliases:` 에 나온 이름, `이름:` 에 나온 이름. 맥북은 `canonical name =` 뒤가 최종 이름입니다
  - 답: www.naver.com,
```bash
Aliases:  www.naver.com, www.naver.com.nheos.com
```

```bash
## DNS 레코드 · TTL · 캐시

### 1. DNS 레코드

- A 레코드: 도메인 이름을 IPv4 주소로 연결.
- AAAA 레코드: 도메인 이름을 IPv6 주소로 연결.
- CNAME 레코드: 도메인 이름을 다른 도메인 이름으로 연결.
- MX 레코드: 해당 도메인의 메일을 처리할 메일 서버를 지정.
- NS 레코드: 해당 도메인의 DNS 정보를 관리하는 네임서버를 지정.
- TTL (Time To Live): DNS 정보를 캐시에 저장해 둘 수 있는 시간(초).
- DNS 캐시: 이전에 조회한 도메인과 IP 주소 등의 DNS 정보를 임시 저장해 재조회 시간을 줄이는 기능.

### 2. DNS 조회 및 확인 명령어

- `nslookup example.com`: 도메인의 IP 주소 조회.
- `nslookup -type=A example.com`: IPv4 주소 조회.
- `nslookup -type=AAAA example.com`: IPv6 주소 조회.
- `nslookup -type=MX example.com`: 메일 서버 정보 조회.
- `nslookup -type=NS example.com`: 권한 있는 네임서버 정보 조회.
- `ipconfig /displaydns`: Windows PC의 DNS 캐시 확인.
- `ipconfig /flushdns`: Windows PC의 DNS 캐시 삭제.

### 3. 알아야 할 팁

#### DNS 캐시와 TTL

- 캐시를 사용하는 이유: 동일한 도메인을 조회할 때 매번 DNS 서버에 질의하지 않아도 되므로 응답 속도가 빨라지고 DNS 서버의 부하가 줄어듦.
- TTL이 남아 있을 때: 캐시에 저장된 DNS 정보를 재사용.
- TTL이 만료되면: 해당 정보를 더 이상 유효한 캐시로 사용하지 않고, 다시 DNS 조회를 수행.
- IP 변경 후 옛 주소로 접속되는 이유: 기존 캐시에 저장된 IP 주소가 TTL 만료 전까지 사용될 수 있기 때문.
- `ipconfig /flushdns`: PC의 DNS 캐시를 비우지만, 공유기나 외부 DNS 리졸버의 캐시까지 삭제하지는 않음.
- 캐시 삭제 후: 도메인에 다시 접속하면 DNS 조회를 수행해 새로운 정보를 받을 수 있음.
- TTL 단위: 초 단위. 예를 들어 TTL이 `300`이면 최대 300초 동안 캐시할 수 있음.

#### DNS 문제 해결

- `nslookup`으로 조회한 주소와 실제 접속 주소가 다르면 캐시, DNS 설정, CDN 등에 따른 차이를 확인.
- `ipconfig /displaydns`에서 특정 도메인이 보이지 않는다고 해서 인터넷이 끊긴 것은 아님. 해당 항목이 캐시에 없을 수 있음.
- DNS 서버가 정상적으로 응답했더라도 도메인이 존재하지 않으면 `Non-existent domain` 또는 `NXDOMAIN`이 나올 수 있음.
- DNS 캐시를 삭제해도 이상한 주소로 계속 연결된다면 DNS 서버 설정, hosts 파일, 브라우저 설정 등을 추가로 점검.
```
