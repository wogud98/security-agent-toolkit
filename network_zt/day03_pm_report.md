### 문제 5-2 · NXDOMAIN 이 많은 PC 찾기

- (가) `day03_5-2_nx_count.py` 의 출력을 그대로 옮겨 적고, 감염이 의심되는 PC 주소를 하나 적어 주세요.
  - 쓸 내용: 출력 한 줄, PC 주소 하나
  - 답: {'10.20.0.42': 3, '10.20.0.33': 1}

- (나-1) `10.20.0.33` 도 NXDOMAIN 을 받았는데, 왜 감염으로 보기 어려울까요?
  - 쓸 내용: ① 그 PC 가 물은 이름이 무엇을 잘못 친 것 같은지 ② 횟수가 몇 번이었는지
  - 답: 사용자 오타 1회

- (나-2) `10.20.0.42` 는 NXDOMAIN 을 세 번 받은 뒤, 마지막에 `qwrtpzkx7v.com` 을 물었을 때는 NOERROR 를 받았습니다. 이게 왜 위험할까요?
  - 쓸 내용: ① 응답이 왔다는 것은 그 이름이 어떤 상태라는 뜻인지 ② 그 이름이 C2 서버라면 다음에 무슨 일이 생기는지
  - 답: NOERROR는 해당 도메인에 대한 DNS 응답이 정상적으로 돌아왔다는 뜻이며, 그 도메인이 C2 서버라면 악성코드가 서버의 IP 주소를 알아내 실제 통신을 시작할 수 있어 위험합니다.

- (다-1) 🔍 DGA 에 감염된 PC 에서는 왜 NXDOMAIN 이 많이 나올까요?
  - 쓸 내용: ① 악성 코드가 이름을 몇 개나 묻는지 ② 그 가운데 실제로 등록된 이름은 몇 개인지
  - 답: DGA 악성코드는 다수의 도메인 이름을 자동 생성해 차례로 질의하지만, 그중 실제로 등록된 이름은 일부에 불과하므로 존재하지 않는 도메인에 대한 NXDOMAIN 응답이 많이 발생합니다.

- (다-2) `nav3r.com` 같은 사칭 도메인은 왜 DGA 지표(길이 · 숫자 · 모음 · NXDOMAIN)로 찾아내기 어려울까요?
  - 쓸 내용: ① 사칭 이름이 어떤 모양으로 만들어지는지 ② 공격자가 등록해 두면 DNS 응답이 어떻게 나오는지
  - 답: nav3r.com 같은 사칭 도메인은 정상 도메인의 철자를 조금 바꾸는 방식으로 만들어져 길이·숫자·모음 특성이 정상 도메인과 비슷하고, 공격자가 해당 도메인을 등록해 두면 DNS에서 정상적으로 응답하므로 NXDOMAIN만으로 탐지하기 어렵습니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요. (「이 교시에 새로 안 것」 칸)
  - 쓸 내용: 새로 안 것 하나와, 그게 왜 기억에 남는지
  - 답:
*DGA	다수의 도메인을 자동 생성하는 알고리즘*
*C2 서버	공격자가 감염된 PC를 원격으로 제어하기 위해 사용하는 서버*
*DNS 질의	도메인에 대한 IP 주소 등의 정보를 요청하는 것*
*NXDOMAIN	해당 도메인이 존재하지 않는다는 DNS 응답*
*NOERROR	DNS 질의가 오류 없이 처리되었다는 응답*
*사칭 도메인	정상 도메인과 비슷하게 만들어 사용자를 속이는 도메인*

- 핵심 정리: 의심 도메인은 길이·숫자·모음·NXDOMAIN 등의 특징으로 1차 탐지할 수 있지만, 정상 도메인도 비슷한 특징을 보일 수 있으므로 여러 지표와 실제 통신 행위를 종합해 판단해야 합니다.
- NXDOMAIN: 질의한 도메인이 존재하지 않는다는 DNS 응답.
- NOERROR: DNS 질의가 오류 없이 처리되었다는 응답으로, 해당 도메인에 대한 레코드가 정상적으로 존재할 수 있음.
- 반복적인 NXDOMAIN: 감염 PC가 DGA로 만든 여러 도메인을 질의하고 있을 가능성이 있음.
