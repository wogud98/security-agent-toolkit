### 문제 5-1 · 지연 · 지터 · 손실을 직접 계산하기

- (가) 회선 X 와 Y 의 평균 지연과 지터(이웃한 두 값의 차이의 평균), 회선 Z 의 손실률을 각각 구해 적어 주세요.
  - 쓸 내용: 「X: 평균 … ms · 지터 … ms / Y: 평균 … ms · 지터 … ms / Z: 손실 … %」

  - 답: Y 가 더 나쁩니다. 평균 지연은 Y 가 26 ms 로 X(30 ms)보다 낮지만 지터가 38 ms 로 X(1 ms)보다 훨씬 큽니다. 화상회의는 도착 간격이 일정해야 해서, 평균이 낮아도 들쭉날쭉하면 끊깁니다.

## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답: 

```
def jitter(got):
    """받은 응답 시간 리스트로 지터를 구한다.

    입력: 응답 시간 리스트 got
    리턴: 이웃한 두 값의 차이의 평균(지터)
    """
    total = 0
    for i in range(1, len(got)):
        total = total + abs(got[i] - got[i - 1])
    return total / (len(got) - 1)
```

- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답: 
  ```
  회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
  회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
  회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
  ```
- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답: ① 리턴값은 이웃한 값의 차이의 평균(지터)입니다. ② measure 의 `jitter_value = jitter(got)` 줄에서 받아 print 에 지터 값으로 씁니다.

### 문제 6-2 · 세 회선을 화상회의 기준으로 판정하기

- (나) 회선 C 는 지연과 지터가 작은데도 왜 부적합인가요? 어제(10/15) 오후 문제 5-2 에서 본 것과 연결해 적어 주세요.
  - 쓸 내용: ① C 의 손실률과 기준 ② 손실이 통신에 주는 영향 한 가지
  - 답: ① 회선 C 는 지연(41.0 ms)과 지터(1.7 ms)가 작지만 손실이 30 % 로 기준 1 % 를 크게 넘습니다. ② 어제(10/15) 오후 문제 5-2 에서 본 것처럼 손실된 패킷은 다시 보내야 합니다(tcp.analysis.retransmission). 실시간 화상회의에서는 도착하지 못한 조각이 화면과 음성의 끊김으로 바로 나타납니다.
- (다) 🔍 `ok` 를 `and` 로 이은 이유는 무엇인가요? `or` 로 이으면 회선 B 의 판정이 어떻게 달라지나요?
  - 쓸 내용: ① `and` 로 이은 이유 ② `or` 로 이으면 B 의 판정이 어떻게 달라지는지
  - 답: ① and 로 이으면 세 기준을 모두 지킬 때만 True 라서 하나라도 넘으면 부적합이 됩니다. ② or 로 이으면 하나만 지켜도 True 가 되어, 회선 B 는 지연(42.3 ms)이 기준 이하라서 지터(54.3 ms)가 기준을 넘는데도 적합으로 잘못 판정됩니다.

  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(어느 회선이 되고 안 되는지, 이유 한 가지)

### 문제 7-1 · tracert 표에서 느려진 구간 찾기

- (가-1) 표 1 에서 지연이 처음 크게 뛴 구간은 몇 번 홉과 몇 번 홉 사이인가요?

  - 답: 4번 홉(6 ms)과 5번 홉(48 ms) 사이
- (가-2) 그 구간은 우리 회사 쪽일까요, 바깥(통신사)일까요? 근거를 적어 주세요.
  - 쓸 내용: ① 「사내 / 바깥」 하나 ② 근거(사내 홉의 시간 또는 장비 이름)
  - 답: ① 바깥(통신사 · 해외) ② 1 · 2번 홉(사내)은 1 ~ 2 ms 로 작고, 4번 홉(통신사 중계 장비)까지도 6 ms 입니다. 뛴 곳이 통신사 중계 장비와 해외 연결 지점 사이라서 우리가 손댈 수 없는 구간입니다.
- (나) 🔍 표 2 의 4번 홉은 60 ms 로 큰데 실제 장애가 아니라고 봅니다. 그 근거는 무엇인가요?
  - 쓸 내용: ① 4번 홉의 뒤 홉 시간 ② 그것이 무엇을 뜻하는지
  - 답: ① 4번 홉만 60 ms 로 크고 다음 5번 홉이 7 ms 로 다시 작아집니다. ② 뒤쪽 홉이 작은 것은 4번 장비가 지나가는 패킷은 빨리 넘겼다는 뜻입니다. 4번 장비가 자기 응답만 늦게 만든 것이라 실제 장애가 아닙니다.

### 4. 한계와 다음 확인

  - 쓸 내용: ① 알 수 없는 것(예: 한 시각의 값이라는 점) ② 다음 확인(시간대를 바꿔 다시 재기 · 구간 운영자에게 확인 요청)
  - 답: ① tracert 는 한 시각의 값이라 일시적 혼잡일 수 있다. ② 시간대를 바꿔 다시 재고, 통신사에 이 구간의 확인을 요청한다.
