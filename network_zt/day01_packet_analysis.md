### ⭐ 도전 2-5 · `ping` 결과를 파이썬으로 판정하기
```python
LIMIT = 100                                       # 이 값(ms)을 넘으면 느리다고 본다

results = [                                       # 문제 2-2 ~ 2-4 에서 본 결과라고 가정합니다
    {"target": "8.8.8.8", "ms": 34},
    {"target": "1.1.1.1", "ms": 120},
    {"target": "192.0.2.1", "ms": None},          # None = 답이 오지 않았다
]

for r in results:                                 # 결과를 하나씩 꺼낸다
    # 1. r["ms"] 가 None 이면 f"[실패] {r['target']} 응답 없음" 을 출력하세요
    if r["ms"] is None:                           # 답이 없었으면 — 맨 먼저 본다
        print(f"[실패] {r['target']} 응답 없음")
    # 2. 아니고 r["ms"] 가 LIMIT 보다 크면 f"[느림] {r['target']} {r['ms']}ms" 를 출력하세요
    elif r["ms"] > LIMIT:                         # 기준보다 오래 걸렸으면
        print(f"[느림] {r['target']} {r['ms']}ms")
    # 3. 그 밖에는 f"[정상] {r['target']} {r['ms']}ms" 를 출력하세요
    else:                                         # 그 밖은 정상
        print(f"[정상] {r['target']} {r['ms']}ms")
```

- 출력 첫 줄:  `[정상] 8.8.8.8 34ms` · `[느림] 1.1.1.1 120ms` · `[실패] 192.0.2.1 응답 없음`

### 문제 3-4 · ARP 캐시 보기 — `arp -a`

- 게이트웨이 줄의 MAC 주소 · 유형:
```bash
arp -a

인터페이스: 192.168.100.51 --- 0x8
  인터넷 주소           물리적 주소           유형
  192.168.1.1           00-10-f3-a3-fc-96     동적        
  192.168.100.8         d8-bb-c1-40-37-22     동적        
  192.168.100.14        d8-bb-c1-51-38-86     동적        
  192.168.100.28        d8-bb-c1-51-3a-00     동적        
```
- 🔍 ARP 는 무엇을 알아내려고 쓰나요? 내 결과의 게이트웨이 줄을 예로 들어 설명합니다.
  - 답:   ARP는 같은 망 안에서 "이 IP 주소를 쓰는 장비의 MAC 주소가 무엇인지"를 알아내려고 쓴다. 내 PC가 인터넷으로 나가려면 먼저 기본 게이트웨이(192.168.1.1)에게 패킷을 넘겨야 하는데, 같은 망 안에서 실제로 전달할 때는 2층 주소인 MAC 주소가 필요하다. 그래서 ARP로 192.168.1.1의 MAC 주소를 물어봤고, 그 답이 내 ARP 캐시의 게이트웨이 줄(192.168.1.1 → ○○-○○-○○-○○-○○-○○)에 저장되어 있다. 유형이 '동적'인 것은 미리 정해 둔 값이 아니라 ARP로 물어봐서 알아낸 값이기 때문이다.

### ⭐ 도전 3-5 · 주소 모양으로 IP 와 MAC 구별하기
```python
def kind(address):
    # 1. address 를 "." 로 나눈 조각이 4개이면 "IP" 를 return 하세요
    if len(address.split(".")) == 4:
      return "IP"
    # 2. address 를 "-" 로 나눈 조각이 6개이면 "MAC" 을 return 하세요
    elif len(address.split("-")) == 6:
      return "MAC"
    # 3. 둘 다 아니면 "모름" 을 return 하세요
    else:
      return "모름"
for a in ["192.168.0.15", "a8-5e-45-01-2b-3c", "ff-ff-ff-ff-ff-ff", "192.168.0"]:
    print(kind(a), a)
```
- 출력 첫 줄: 
```
IP 192.168.0.15
MAC a8-5e-45-01-2b-3c
MAC ff-ff-ff-ff-ff-ff
모름 192.168.0
```
### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: 
- **IP(3층)** – 망에서 나를 찾아오는 위치 주소 (점 4덩어리)
- **MAC(2층)** – 장치 고유 번호, 같은 망 안 전달에 쓴다 (`-` 6덩어리)
- **기본 게이트웨이** – 바깥 인터넷으로 나가는 출구 장비(공유기)의 IP
- **ipconfig //all** – MAC은 `//all` 로 봐야 나온다 (Git Bash는 슬래시 두 번)
- **ARP / ARP 캐시** – IP로 MAC을 묻는 방법, 그 답을 저장한 표. `동적`=물어서 알아냄, `정적`=미리 정해짐
- **ff-ff-ff-ff-ff-ff** – 같은 망 전체에 보내는 브로드캐스트 주소
- **ARP 스푸핑** – 게이트웨이 IP의 MAC이 평소와 달라지면 의심

- 세 패킷의 순서와 방향: 내 피시가(나) - 서버가(다) - 내 피시가(가)
- 🔍 연결을 맺을 때는 세 번인데, 끝낼 때는 왜 네 번인가요?
  - 답: 맺을 때는 서버의 ACK 와 SYN 이 동시에 참이라 한 신호에 같이 실을 수 있다. 끝낼 때는 서버가 「알았다(ACK)」는 바로 답하지만 아직 보낼 데이터가 남아 있을 수 있어 「나도 다 보냈다(FIN)」를 나중에 따로 보낸다.

### 문제 5-4 · 같은 서버로 간 두 연결은 무엇이 다른가
```BASH
프로토콜  로컬 주소              외부 주소              상태
TCP    192.168.0.15:51234     142.250.196.110:443    ESTABLISHED
TCP    192.168.0.15:51240     142.250.196.110:443    ESTABLISHED
```
- 두 연결에서 같은 것 · 다른 것: 외부주소(목적지/IP/포트) 동일, 로컬주소의 포트(임시주소)는 다르다.
- 같은 서버로 간 두 연결을 무엇으로 구별하나요?
  - 답: 목적지와 내 IP 가 같으니 내 PC 가 연결마다 *다른 임시 포트를 골라 구별*한다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:
- **TCP vs UDP** – TCP 는 연결을 맺고 받았는지 확인하며 보내고(웹·파일), UDP 는 연결 없이 바로 보낸다(DNS·실시간 영상)
- **ICMP** – ping 이 쓰는 별도 방식. TCP 도 UDP 도 아니다
- **3-way handshake** – SYN → SYN, ACK → ACK 세 번으로 연결을 맺고 ESTABLISHED 가 된다
- **연결 종료** – FIN · ACK · FIN · ACK 네 번. 서버는 보낼 데이터가 남아 있을 수 있어 FIN 을 따로 보낸다
- **플래그** – SYN 연결하자 · ACK 받았다 · FIN 다 보냈다 · RST 바로 끊는다
- **연결을 가리키는 네 값** – 출발지 IP·포트, 목적지 IP·포트. 같은 서버로의 연결은 임시 포트로 구별한다
- **in vs ==** – 리스트 안에 값이 있는지는 `in`, `리스트 == 값` 은 늘 False
