- 모델·승인 기준·폴더·알림 주소는 config.json 에 뺐다. config_off.json(꺼진 서버)으로 돌려도 [알림 실패] 만 찍고 보고서는 남았고, 도전 4-6 에서는 report_folder 값대로 reports/ 폴더를 만들어 보고서를 모았다
- make_lines · needs_approval · parse_llm_json 테스트 9건을 test_agent_core.py 에 모아 명령 한 번으로 확인한다

## 가장 어려웠던 것
- LLM 응답을 확인 없이 꺼낸 것. 10/6 에 `data["choices"][0]` 에서 `TypeError: list indices must be integers` 가 났고, 같은 날 ReadTimeout 도 났다. 성공 응답과 실패 응답의 모양이 다르다는 것을 몰랐다
  → `print(data)` 로 응답을 직접 찍어 구조를 확인했고, 이후에는 상태 코드부터 보고 실패하면 "" 를 돌려주게 했다
- 노트북 셀과 터미널을 구분하는 것. 10/2 에 curl 명령을 파이썬 셀에 넣어 SyntaxError 가 났고, 서버를 안 켠 채 보내 `Failed to connect` 도 봤다
  → 셸 명령은 터미널에서, 서버는 켜 둔 터미널과 실행하는 곳을 나눠 쓰는 습관이 생겼다
- import 와 `if __name__ == "__main__":`. import 만 했는데 보고서가 왜 안 만들어지는지 헷갈렸다
  → import 는 모듈의 최상위 코드를 실행하므로, 직접 실행할 코드만 `if __name__` 안에 둬 구분한다

## 리뷰에서 찾은 것과 고친 것
- 문제 5-2 에서 다섯 항목을 코드를 보고 판정하지 않고 인덱스를 두 칸씩 건너뛰며 "위반" 을 넣었다. 위반 수 3개는 맞았지만 항목이 틀렸다(정답은 설정·실패·기록). 에러 없이 틀린 값 — 논리 에러를 내 코드에서 직접 겪었다
  → 다시 읽어 보니 모델 이름이 코드에 직접 적혀 있었고, 요청에 timeout 이 없었고, `except: pass` 로 실패를 숨기고 있었다
- 6-5: high 가 4건인데 0건으로 나왔다. 디버그 줄로 찍어 보니 "High"·"HIGH" 같은 대소문자와 "high "·" high" 같은 앞뒤 공백, 원인이 두 개였다 → `.strip().lower()` 로 고쳤다
- 도전 6-6: 경고 기준(`>` → `>=`), 정렬 순서(low 부터 → high 부터), 줄 끝 `\n` 누락 세 곳을 찾아 고치고 고친 곳마다 assert 를 붙였다
- 9/30 에 조회 실패 IP 를 결과에서 버리지 않고 "unkown" 으로 남기게 바꿨는데, 다시 보니 출력이 isp 대신 ip 를 찍고 있었고 "unknown" 철자도 틀려 있었다 — 테스트가 없으면 이런 것이 그대로 남는다
